# 浏览器插件版（X Auto SOP Extension）

Python 版的「同门」：同一套 SOP 判定与评论生成逻辑移植成 MV3 扩展，
不再依赖调试端口和 SendInput，装进 Edge/Chrome 就能跑。

## 与 Python 版的分工

| | Python 版（`xauto/`） | 插件版（`extension/`） |
|---|---|---|
| 输入方式 | Win32 SendInput（真实鼠标键盘，需要前台） | CDP `Input.dispatch*`（chrome.debugger，可信事件，**不需要前台**） |
| 会话循环 | 子进程 + UI 控制台 | content script 状态机 + sessionStorage 跨导航恢复 |
| 调度 | UI server / x_repeat | `chrome.alarms`：每 30 分钟自动开一轮 30 分钟会话 |
| SOP 判定 | `xauto/sop.py` | `extension/sop.js`（逐条移植，规则一致） |
| 评论生成 | `xauto/comment.py` | `extension/comment.js`（同一套 prompt/模板/校验） |
| 留档 | `data/tweets.jsonl` | `chrome.storage.local`，面板一键导出 JSON |

## 文件结构

```
extension/
  manifest.json    MV3：debugger/storage/tabs/scripting/sidePanel/alarms
  sop.js           SOP 判定层（跳过/质量分/展开/赞/评/校验/关注/通知）
  comment.js       评论生成（LLM 经 background 代发；无密钥走模板兜底）
  content.js       页面操作 + 会话状态机（home→detail→profile→notif）
  background.js    CDP 拟人输入（贝塞尔分步移动/逐字 130ms/滚轮 120 单位）+ LLM 代发 + 轮次 alarm
  dashboard.html/js 使用窗口（点工具栏图标打开）：控制面板/帖子留档/活动日志/使用说明 四页签，
                   今日额度进度条、会话统计、留档筛选表格、修复页面注入、导出记录
  panel.html/js    侧边栏（轻量入口：开始/停止/循环/参数 + 跳控制台）
```

## 使用窗口（dashboard）

点浏览器工具栏的扩展图标 → 弹出独立控制台窗口（1180×860）：

- **控制面板**：开始/停止/循环；行为参数分组排版（节奏 / 评论 / 互动 / 关注发现 / 其他 + 高级判定）；
  LLM Key 与每日上限；额度与统计卡片**可点开看明细**；当前会话统计（读/展开/赞/评/藏/关注/滑过）
- **统计可下钻**：点「今日点赞 / 评论 / 关注 / 留档条数 / 累计已回过的帖子」或会话统计任一格，
  弹出抽屉列出**具体做了什么**——时间、作者（可点回原帖）、帖子内容、我发的评论全文、跳过原因；
  按 Esc 或点遮罩关闭
- **日志分色 + 筛选**：点赞粉、评论蓝、关注黄、滑过灰、失败红、读帖浅灰、判定中灰、导航紫、等待土黄；
  日志页可按类型筛选，帖子留档页可按动作筛选（只看评论/点赞/关注/收藏/滑过）
- **帖子留档**：表格浏览全部留档记录（时间/作者可点回原帖/内容/动作徽章），支持关键词+动作筛选
- **活动日志**：滚动实时日志（content 的 logAct 全走这里）
- **实时视窗**：当前正在读的帖子 + **全部历史活动**（260px 可上下滑动的滚动区，贴底自动跟随，
  往上翻看历史时不会被抢滚动条）
- **使用说明**：30 秒上手 + SOP 规则摘要 + 故障处理速查
- 维护按钮：**重新注入**（手动兜底，正常不需要点 —— 见下方「自动注入」）、导出全部记录 JSON

## 评论规则（两套并存，面板切换）

**默认 = 我的规则**（`comment_rule: "mine"`），原 SOP 规则完整保留，面板「评论规则」一键切回。

### 我的规则（当前默认）
| 项 | 规则 |
|---|---|
| 适用帖子 | **什么帖子都能评** —— 不再按长度/质量分拦；只有纯图/纯链接（无正文）、命中广告互关骂战词（`shouldSkip`）的帖子不碰 |
| 字数 | **硬上限 20 字**；目标字数面板可调（默认 **13**），实际在 目标±5 内**随机浮动**，不是写死 |
| 内容 | **回应帖子 + 表达观点**：先用半句接住原帖的具体短语，再给态度/判断 |
| 生成 | 配了 LLM → 提示词要求「① 对内容有具体回应 ② 表达自己观点」，并附上**已有回复**和**我以前发过的评论**要求别重复；没配 → 12 条短句模板，`{p}` 只填**完整可读**的短语，取不到就退回纯观点句 |

**短语提取纪律（2026-11-18 修）**：以前 `shortPhrase` 只挑最长子句再硬截，会拼出
`5、开源免…，短期热闹长期未必。` 这种机器痕迹明显的句子。现在四道过滤：
① 数字/序号开头的子句直接丢；② **自带省略号的残句**直接丢；③ 全是虚词/口语填充的丢；
④ 只返回能独立读通的完整片段 —— **取不到就返回空**，改用「不带 {p} 的纯观点句」，
而不是硬切出「半导体周期见」「我觉得这个工」这类断词。实测 50 条：省略号残留 0、空结果 0。

**防重复评论（2026-11-18 加）**：三层——
① 同一帖 ID 只评一次（`replied` 表）；
② **同一作者**：`withAntiRepeat()` 把他名下所有评论过我发过的句子带进生成上下文，
LLM 提示词里明写「绝对不要再说一遍」，模板生成也会跳过；
③ **全局**：最近 100 条历史做字符二元组相似度比对，≥0.6 判重复，LLM 会换角度重写、
模板会换下一条。`noteComment()` 在每条评论成功后立即入历史。
| 校验 | 只卡：空评论、纯表情/符号、<4 字、互动交换（互关求关注）、编造亲历。**不设字数硬上限**，不强制截断 |
| 去重 | 同一帖默认只回一次（面板「评论去重」可关） |

### 发送前审核（`review.js`，2026-11-19 加）

生成之后、发送之前，每条评论都要过一遍评分闸。**不到及格线就跳过这条，绝不发出去**。

| 维度 | 分值 | 看什么 |
|---|---|---|
| 观点强度 | 30 | 有没有判断/因果/条件/取舍。只说「说得对」「收藏了」→ 5 分 |
| 与帖相关度 | 25 | 是否接住帖子的具体内容。字面重合 + 话题实词 + **同场景**三路判定 |
| 人味 | 20 | AI 腔（综上所述/不容忽视）、编造亲历（我测过/我朋友） |
| 长度完整度 | 15 | 太短没信息、太长像论文、结尾不能是逗号或悬空连接词 |
| 复述原帖 | −35 | 把作者的话照搬回来说成自己的 |
| 老评论重复 | −25~30 | 和发过的、或给同一作者发过的太像 |

**一票否决**（不管多少分都不发）：直角引号「」、议论文腔（综上所述/首先/其次）、
引流词（互关 / @ / # / 点击链接）、冒充 AI、纯符号表情、纯态度短句。

日志里会写明扣了什么分、为什么，例：
`评论不通过审核（47 分 · 质量分不足（47 < 60））→ 跳过这条，不发`。
及格线（默认 60）和额外禁用词在**评论规则窗口**里调。

**为什么不让字面重合决定一切**：整句模板不引用原帖短语，字面命中天然为 0，
但它是按场景写的（亏损帖配亏损句），本来就相关。所以相关度用三路判定：
字面滑窗 → 话题实词 → 场景一致，任一命中都不判跑题；三路全落空才重罚。

### 原 SOP 规则（切到 `sop` 生效）
- 互动帖：`max(评论概率, 0.6)`；普通帖：正文 ≥10 字，<15 字必须命中重点领域，质量分 ≥1.2 或命中重点领域
- 禁空话（说得很好/受益匪浅/干货…）、禁编造亲历、禁互动交换、必须接住原帖具体点（`specificOverlap ≥1`）、按场景分型
- 长度由「长度档」控制（短 10~25 / 正常 20~60 / 详细 60~120 字）

两套规则共用：评论概率（默认 0.85）、每日 `max_reply` 上限、逐字 130ms 输入、提交后证据校验、
评论之间随机间隔（面板「写操作间隔」上下限，默认 30~90 秒 × 速度系数）。

## SOP 参数控制面板

控制台「行为参数」+「SOP 判定参数（高级）」两栏，全部参数可见可改：

| 分组 | 参数 |
|---|---|
| 节奏 | 会话分钟、打字 ms/字、速度系数、写操作间隔上下限 |
| 概率 | 展开 / 点赞 / 评论 / 收藏 / 发现页概率；点赞概率上限、评论概率上限 |
| 评论 | 评论规则（我的/SOP）、目标字数（5~40，无硬上限）、评论去重开关 |
| 内容 | 首页 Feed、语气档、长度档（SOP 模式用）、重点关键词（逗号分隔，命中加权） |
| 关注 | 每轮关注上限 |
| 额度 | 日赞、日评、日关注上限 |
| 判定 | 展开字数门槛（正文超过就点进详情） |

保存后**下一次会话生效**；点保存时状态栏会提示当前生效的评论规则和字数。

## 通知页三类分流（2026-11-18 加）

按用户策略，通知页的条目分三类处理：

| 通知类型 | 识别特征 | 处理 |
|---|---|---|
| **别人回复我的帖子** | `Replying to @我` / `replied to` / `回复了你` / `mentioned you` | 点进去回复。**回复时同时读两条内容**：我的原帖（上下文）+ 他具体说了什么（要接住的点），生成对话式回应 |
| **别人关注我** | `followed you` / `关注了你` | 点**这个人的**头像进主页（聚合卡片里有多个头像时按 handle 精确匹配，不会点错人），走「翻 10 条 + 随机互动 3~5 篇 + 关注」；处理完**回通知页**继续下一条；已关注过的跳过 |

> **通知阶段默认开启**（`notif_enabled: true`）。通知列表是虚拟列表，进入后会先滚动加载多屏再收集，
> 否则底部的新粉丝读不到。回复类占会话前 20% 时间、关注类额外给到 40%，互不挤占。
| **别人点赞我的帖子** | `liked your post` / `喜欢了你的` | **不处理**，只计数写日志 |

其它类型（转发、系统通知）一律忽略。

## 关注限流（防封号，三道闸）

新号短时间大量关注是最容易被平台抓的行为。**任何关注路径**（详情页、发现页就地关注、
新粉丝主页、作者主页）都必须先过 `followAllowed()`：

| 闸门 | 默认 | 说明 |
|---|---|---|
| 两次关注间隔 | **60~180 秒随机** | 每次随机一个目标间隔，没到就不关注，日志写「距上次关注才 X 秒」 |
| 每小时上限 | **8 次** | 硬限流。新号建议 5~8；日志写「本小时已关注 X/8」 |
| 每日上限 | **25 次**（沿用 `max_follow`） | 达上限当天不再关注 |
| 单轮上限 | **5 次**（`follow_per_session`） | 一轮会话内最多关注几个 |

前三项在控制台「关注 / 发现」分组里都能调。所有关注成功都走 `noteFollow()` 统一记账，
不会出现某条路径绕过限流的情况。

## API 配置（存本地，不用每次填）

控制台「API 配置」卡片里填 Key / Base URL / 模型 → 点「保存 API 配置」。

- 存在 `chrome.storage.local` 的独立键 `xa_llm` 里，**下次打开自动带出**，
  只显示前 4 位 + 后 4 位（中间打码）。
- **留空保存 = 保持原值**，不会把已存的 Key 清掉；要清除请点「清除 Key」。
- 「保存设置」也改成**合并写入**——以前侧边栏和控制台字段不同，整体覆盖会互相
  抹掉对方保存的字段，这就是「Key 每次都要重填」的原因（已修）。
- 密钥只留在本机浏览器，除了发给你填的模型接口（api.deepseek.com 等）之外不发给任何地方。

## 评论规则窗口（独立页面）

控制台「评论规则」卡片 → **打开评论规则窗口**（`comment-rule.html`），一页看全、改全：

| 区块 | 内容 |
|---|---|
| 当前规则 | 「我的规则」/「原 SOP 规则」切换 |
| 触发条件 | 评论概率、概率上限、同一帖只回一次、重点领域关键词 |
| 字数与长度 | 目标字数（5~20，实际 ±5 随机，硬上限 20）、长度档（SOP 用） |
| 语气与风格 | 随和/专业/幽默/好奇/共情/直接 |
| **提示词** | 整段 system 提示词，可直接编辑；支持占位符 `{len} {lo} {hi} {cap} {tone} {post}`，点占位符标签插入到光标处；可一键恢复默认 |
| **模板句** | 没配 Key 时用的短句池，一行一句，`{p}` 自动替换成原帖短语；显示条数和「哪些没带 {p}」 |
| **实时预览** | 用示例帖子模拟生成 6 条，显示每条字数和是否超 20 字 —— 不调用模型 |

保存写回 `xa_settings`（同样合并写入），**下一轮会话生效**。

## 自动注入（2026-11-18 改：不再需要手动点）

「注入页面」按钮只对**当前那个 x.com 标签页**做一次性注入，这是以前要反复手点的根源。
现在注入全自动，三层兜底（都幂等，content.js 有 `__XA_LOADED__` 守卫）：

1. **manifest 声明**：任何 x.com 页面加载时自动注入（浏览器原生机制）。
2. **标签页加载完成兜底**：background 监听 `tabs.onUpdated`，x.com 加载完成补一次。
3. **扩展重载/更新/浏览器启动兜底**：`onInstalled` / `onStartup` 时把所有已开着的
   x.com 标签页全部补注入（扩展重载后旧页面里的脚本上下文会失效，这是以前
   「要一直点注入」的真正原因）；控制台发现未注入也会自动补，不再提示手点。

注入后脚本驻留页面：**滚动、点进帖子、返回都不需要重新注入**（X 是单页应用，
不换文档）。控制台「重新注入」按钮仅作极端情况的手动兜底。

侧边栏（panel）保留作轻量入口，里面「控制台」按钮也能打开这个窗口。

## 安装（Edge，和现有调试浏览器互不干扰）

1. 地址栏开 `edge://extensions`（Chrome 是 `chrome://extensions`）
2. 打开右下角「开发人员模式」
3. 「加载解压缩的扩展」→ 选 `extension/` 目录
4. 打开 x.com 登录小号 → 点工具栏图标开侧边栏
5. 「开始一轮会话」手动跑一轮；「循环：开」= 每 30 分钟自动开一轮 30 分钟首页时间线
6. 面板里填 LLM Key（DeepSeek）；不填就模板兜底，一样过 SOP 校验

## 已知边界（诚实记录）

- **慢网加载监控（2026-11-18 加）**：网速慢时 DOM 分批渲染，「点了就动」会打在
  旧页面上。现在所有导航/切栏目/滚动/进详情后都有等待：转圈（`[role=progressbar]`，
  排除视频音量条）消失 + 帖子数量连续两次轮询稳定 + 内容签名真的变化，才继续。
  滚动后额外等新帖追加；连续 3 次滚动没新帖 = 到头或加载不出，滑回顶部等下一轮。
  等待超时会写日志并「按当前状态继续」，不会死等卡住会话。
- **实时视窗**：控制面板顶部卡片显示当前正在读的帖子（作者/领域标签/正文摘要），
  下面是一条 280px 高、**可上下滑动**的历史活动区，保留全部活动记录（最多 300 条），
  按动作**分色显示**，贴底时自动跟随最新一条；往上翻历史时不会被强行拉回底部。
- **活动日志结构化（2026-11-18）**：`activity` 每条新增 `kind` 字段（read/judge/like/cmt/
  follow/skip/fail/nav/wait/info），由 `logAct(msg, kind)` 显式传入，老调用点由 `guessKind()`
  按文案兜底推断。UI 的颜色、筛选、统计下钻全部依赖这个字段，**别再用文案匹配做分类**。
- **不碰自己的帖子（2026-11-18 加，硬规则）**：选帖时就把 `handle === 我` 的帖子/回复
  过滤掉——不点进去、不赞、不评。详情页、通知回复、作者主页三条路径各有独立兜底检查。
  之前漏了这层，导致在自己的回复下面连续回复自己 3~4 次（号自己跟自己对话，平台最容易
  判定刷量）。整屏都是自己的帖子会自动往下翻，连续 4 屏仍全是则回顶部拉新一批。
  读不到自己的账号名时会在日志里**显式告警**，不会静默失效。
- **时间线刷新（2026-11-18 改）**：优先点顶部的 **「Show N posts」** 按钮或蓝色
  「新帖」箭头拉新帖（真人就是这么做的），没有按钮才滚回顶部。并且加了门槛
  ——**本轮读满 `min_read_before_refresh`（默认 12）篇之前不回顶刷新**，
  避免反复刷同几条帖子。日志会写「本轮才读 X/12 篇 —— 继续往下翻，先不刷新」。
- **时间线无限流处理**：X 的时间线新帖在上方，一直往下滑会滑进旧帖区。现在的策略：
  ① 滚动后先等新帖追加（最多 20 秒，慢网分页请求晚到是常态）；② 连续两轮滚动都没有
  新帖且已读够篇数 → 点「Show N posts」/「新帖」箭头回顶拉新，没有则滚轮回到顶部；
  ③ 仍然没变化就停 8~15 秒再继续，不会死循环卡住。滑过自己的帖子也算一次滚动。
- **全文记录（2026-11-18 改）**：之前正文只截 400 字；现在 `readTweets` 读**整条正文**，
  卡片里折叠的长文（Show more）会先展开再判定，留档写的是全文，日志会标注「全文 N 字」、
  展开成功时提示「展开长文：X → Y 字」。注意：X 的详情页本身不折叠，时间线折叠的
  长文只有真点开「显示更多」才能拿全——程序现在会替你点这一下。
- **发现页找人**：首页每读 5 篇去一次发现页（Explore），收集页面上出现的可关注用户。
  `explore_prob`（默认 0.5，面板可调）的含义是：**未关注的用户里，有多大概率点进主页
  浏览 10 条 + 随机互动 3~5 篇 + 关注**；**没命中的不是跳过，而是直接在那一行点关注**
  （不进主页），把关注量做起来。两者都受 `max_follow` 每日上限约束。
- **开始前先刷新（2026-11-18 加）**：`startSession()` 会先点「Show N posts」/「新帖」
  按钮拉最新一批；没有按钮就滚到顶再点一次首页 tab 触发重载。
- **会话统计实时（2026-11-18 加）**：以前只在阶段切换时同步，读帖期间控制台数字是冻的。
  现在 `startStatsSync()` 每 1.5 秒把 stats/phase/now 快照写进 storage，`stopSession()` 清理定时器。
- **重点领域加权**：股市 / AI / 半导体 / 经济 命中的帖子质量分 +2、赞评概率各 +0.15；
  互动帖（回复我、向我提问）即使内容薄也允许回。看到的所有帖子都按概率摇赞/摇评，
  主动多互动做权重（2026-11-18：短帖 ≥10 字且命中重点领域也放行评论；评论概率默认
  提到 0.85）。要评论就自动点进详情页。
- **关注（2026-11-18 改：先翻主页互动再关注，不判方向）**：详情页右侧 Relevant People
  直接读关注态（Follow/Following），不必为「查看」而点进主页。未关注 → 进其主页
  **浏览 10 条帖子（不够就滚动加载，逐条读全文）→ 随机抽 3~5 篇、每篇随机赞或评**
  → 最后**直接关注**（用户策略：不看方向/质量，涨互动、涨时间线）。关注成功以按钮
  翻成已关注态为准；主栏范围查按钮，避免把右侧「Who to follow」别人的按钮当成作者的。
  单会话关注上限默认 5，每日上限 max_follow 仍守住。
- **落点校验（2026-11-18 加）**：`getBoundingClientRect` 给的 CSS 坐标和 CDP
  `Input.dispatchMouseEvent` 的实际落点之间可能有系统性偏差（页面缩放、时间线
  自动滚动、窗口状态都会引入）。第一版没校验就点 → 表现为「反复在一个空点上
  点了又退、退了又点」。现在每次点击前先把鼠标移过去、检查目标元素是否进入
  `:hover`，不中就按由近及远扫描修正（±24px），并累计学习全局偏移；会话开始
  还会用导航锚点先标定一次。**如果标签页不可见导致 `:hover` 永远不亮，连续
  3 次失败后自动退回直点模式**（日志会说明）。要校验全程有效，x.com 标签页
  保持可见（可以是活动标签页，窗口不必前台）。
- **速度系数**：面板「速度系数」默认 1.5（= 比第一版慢一半）。它作用于移动、
  悬停、按压、滚动间隔和所有阅读停顿；打字仍由「打字 ms/字」单独控制（默认
  130 不动）；提交后的证据轮询不乘系数（那是等服务器，不是人的节奏）。
- **首页 Feed 栏目策略（2026-11-18 改）**：默认在「**为你推荐**」刷；连续两次刷新都拉不出新帖
  （`refreshOrTop` 返回 `topped`/`timeout`）→ 自动切到「**正在关注**」；那边也没新帖就切回
  「为你推荐」，两个栏目来回换着找内容。切换后清空「已读过」记录与读帖计数（两个栏目的内容不同）。
  栏目识别同时认中英文（`为你推荐/For You`、`正在关注/Following`），切之前会先看当前选中的
  是哪个，已经对了就不重复点击（切栏目会触发时间线重载，能省则省）。
- CDP 事件可信但没有 OS 级轨迹：贝塞尔移动是逐点 `mouseMoved` 模拟的，
  比 SendInput 差一档（不带真实硬件时序抖动）。风险等级：介于合成事件和真实键鼠之间。
- 页面必须保持打开（可以后台标签页，不用前台）；**别关那个标签页**，会话状态在 sessionStorage。

- 同机如果 Python 版也在操作同一个 x.com 标签页，会互相抢焦点——二选一跑。
