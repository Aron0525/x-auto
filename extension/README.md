# 浏览器插件版（X Auto SOP Extension）

Python 版的「同门」：同一套 SOP 判定与评论生成逻辑移植成 MV3 扩展，
不再依赖调试端口和 SendInput，装进 Edge/Chrome 就能跑。

## 与 Python 版的分工

| | Python 版（`xauto/`） | 插件版（`extension/`） |
|---|---|---|
| 输入方式 | Win32 SendInput（真实鼠标键盘，需要前台） | CDP `Input.dispatch*`（chrome.debugger，可信事件，**不需要前台**） |
| 会话循环 | 子进程 + UI 控制台 | content script 状态机 + sessionStorage 跨导航恢复 |
| 调度 | UI server / x_repeat | `chrome.alarms`：每 30 分钟自动开一轮 30 分钟会话 |
| SOP 判定 | `xauto/sop.py` | `extension/sop.js`（逐条移植，规则一致） |
| 评论生成 | `xauto/comment.py` | `extension/comment.js`（同一套 prompt/模板/校验） |
| 留档 | `data/tweets.jsonl` | `chrome.storage.local`，面板一键导出 JSON |

## 文件结构

```
extension/
  manifest.json    MV3：debugger/storage/tabs/scripting/sidePanel/alarms
  sop.js           SOP 判定层（跳过/质量分/展开/赞/评/校验/关注/通知）
  comment.js       评论生成（LLM 经 background 代发；无密钥走模板兜底）
  content.js       页面操作 + 会话状态机（home→detail→profile→notif）
  background.js    CDP 拟人输入（贝塞尔分步移动/逐字 130ms/滚轮 120 单位）+ LLM 代发 + 轮次 alarm
  dashboard.html/js 使用窗口（点工具栏图标打开）：控制面板/帖子留档/活动日志/使用说明 四页签，
                   今日额度进度条、会话统计、留档筛选表格、修复页面注入、导出记录
  panel.html/js    侧边栏（轻量入口：开始/停止/循环/参数 + 跳控制台）
```

## 使用窗口（dashboard）

点浏览器工具栏的扩展图标 → 弹出独立控制台窗口（1180×860）：

- **控制面板**：开始/停止/循环；行为参数分组排版（节奏 / 评论 / 互动 / 关注发现 / 其他 + 高级判定）；
  LLM Key 与每日上限；额度与统计卡片**可点开看明细**；当前会话统计（读/展开/赞/评/藏/关注/滑过）
- **统计可下钻**：点「今日点赞 / 评论 / 关注 / 留档条数 / 累计已回过的帖子」或会话统计任一格，
  弹出抽屉列出**具体做了什么**——时间、作者（可点回原帖）、帖子内容、我发的评论全文、跳过原因；
  按 Esc 或点遮罩关闭
- **日志分色 + 筛选**：点赞粉、评论蓝、关注黄、滑过灰、失败红、读帖浅灰、判定中灰、导航紫、等待土黄；
  日志页可按类型筛选，帖子留档页可按动作筛选（只看评论/点赞/关注/收藏/滑过）
- **帖子留档**：表格浏览全部留档记录（时间/作者可点回原帖/内容/动作徽章），支持关键词+动作筛选
- **活动日志**：滚动实时日志（content 的 logAct 全走这里）
- **实时视窗**：当前正在读的帖子 + **全部历史活动**（260px 可上下滑动的滚动区，贴底自动跟随，
  往上翻看历史时不会被抢滚动条）
- **使用说明**：30 秒上手 + SOP 规则摘要 + 故障处理速查
- 维护按钮：**重新注入**（手动兜底，正常不需要点 —— 见下方「自动注入」）、导出全部记录 JSON

## 评论规则（两套并存，面板切换）

**默认 = 我的规则**（`comment_rule: "mine"`），原 SOP 规则完整保留，面板「评论规则」一键切回。

### 我的规则（当前默认）
| 项 | 规则 |
|---|---|
| 适用帖子 | **什么帖子都能评** —— 不再按长度/质量分拦；只有纯图/纯链接（无正文）、命中广告互关骂战词（`shouldSkip`）的帖子不碰 |
| 字数 | **硬上限 20 字**；目标字数面板可调（默认 **13**），实际在 目标±5 内**随机浮动**，不是写死 |
| 内容 | **回应帖子 + 表达观点**：先用半句接住原帖的具体短语，再给态度/判断 |
| 生成 | 配了 LLM → 提示词要求「① 对内容有具体回应 ② 表达自己观点」，并附上**已有回复**和**我以前发过的评论**要求别重复；没配 → 12 条短句模板，`{p}` 只填**完整可读**的短语，取不到就退回纯观点句 |

**短语提取纪律（2026-11-18 修）**：以前 `shortPhrase` 只挑最长子句再硬截，会拼出
`5、开源免…，短期热闹长期未必。` 这种机器痕迹明显的句子。现在四道过滤：
① 数字/序号开头的子句直接丢；② **自带省略号的残句**直接丢；③ 全是虚词/口语填充的丢；
④ 只返回能独立读通的完整片段 —— **取不到就返回空**，改用「不带 {p} 的纯观点句」，
而不是硬切出「半导体周期见」「我觉得这个工」这类断词。实测 50 条：省略号残留 0、空结果 0。

**防重复评论（2026-11-18 加）**：三层——
① 同一帖 ID 只评一次（`replied` 表）；
② **同一作者**：`withAntiRepeat()` 把他名下所有评论过我发过的句子带进生成上下文，
LLM 提示词里明写「绝对不要再说一遍」，模板生成也会跳过；
③ **全局**：最近 100 条历史做字符二元组相似度比对，≥0.6 判重复，LLM 会换角度重写、
模板会换下一条。`noteComment()` 在每条评论成功后立即入历史。
| 校验 | 只卡：空评论、纯表情/符号、<4 字、互动交换（互关求关注）、编造亲历。**不设字数硬上限**，不强制截断 |
| 去重 | 同一帖默认只回一次（面板「评论去重」可关） |

### 发送前审核（`review.js`，2026-11-19 加）

生成之后、发送之前，每条评论都要过一遍评分闸。**不到及格线就跳过这条，绝不发出去**。

| 维度 | 分值 | 看什么 |
|---|---|---|
| 观点强度 | 30 | 有没有判断/因果/条件/取舍。只说「说得对」「收藏了」→ 5 分 |
| 与帖相关度 | 25 | 是否接住帖子的具体内容。字面重合 + 话题实词 + **同场景**三路判定 |
| 人味 | 20 | AI 腔（综上所述/不容忽视）、编造亲历（我测过/我朋友） |
| 长度完整度 | 15 | 太短没信息、太长像论文、结尾不能是逗号或悬空连接词 |
| 复述原帖 | −35 | 把作者的话照搬回来说成自己的 |
| 老评论重复 | −25~30 | 和发过的、或给同一作者发过的太像 |

**一票否决**（不管多少分都不发）：直角引号「」、议论文腔（综上所述/首先/其次）、
引流词（互关 / @ / # / 点击链接）、冒充 AI、纯符号表情、纯态度短句。

日志里会写明扣了什么分、为什么，例：
`评论不通过审核（47 分 · 质量分不足（47 < 60））→ 跳过这条，不发`。
及格线（默认 60）和额外禁用词在**评论规则窗口**里调。

**为什么不让字面重合决定一切**：整句模板不引用原帖短语，字面命中天然为 0，
但它是按场景写的（亏损帖配亏损句），本来就相关。所以相关度用三路判定：
字面滑窗 → 话题实词 → 场景一致，任一命中都不判跑题；三路全落空才重罚。

### 原 SOP 规则（切到 `sop` 生效）
- 互动帖：`max(评论概率, 0.6)`；普通帖：正文 ≥10 字，<15 字必须命中重点领域，质量分 ≥1.2 或命中重点领域
- 禁空话（说得很好/受益匪浅/干货…）、禁编造亲历、禁互动交换、必须接住原帖具体点（`specificOverlap ≥1`）、按场景分型
- 长度由「长度档」控制（短 10~25 / 正常 20~60 / 详细 60~120 字）

两套规则共用：评论概率（默认 0.85）、每日 `max_reply` 上限、逐字 130ms 输入、提交后证据校验、
评论之间随机间隔（面板「写操作间隔」上下限，默认 30~90 秒 × 速度系数）。

## SOP 参数控制面板

控制台「行为参数」+「SOP 判定参数（高级）」两栏，全部参数可见可改：

| 分组 | 参数 |
|---|---|
| 节奏 | 会话分钟、打字 ms/字、速度系数、写操作间隔上下限 |
| 概率 | 展开 / 点赞 / 评论 / 收藏 / 发现页概率；点赞概率上限、评论概率上限 |
| 评论 | 评论规则（我的/SOP）、目标字数（5~40，无硬上限）、评论去重开关 |
| 内容 | 首页 Feed、语气档、长度档（SOP 模式用）、重点关键词（逗号分隔，命中加权） |
| 关注 | 每轮关注上限 |
| 额度 | 日赞、日评、日关注上限 |
| 判定 | 展开字数门槛（正文超过就点进详情） |

保存后**下一次会话生效**；点保存时状态栏会提示当前生效的评论规则和字数。

## 通知页三类分流（2026-11-18 加）

按用户策略，通知页的条目分三类处理：

| 通知类型 | 识别特征 | 处理 |
|---|---|---|
| **别人回复我的帖子** | `Replying to @我` / `replied to` / `回复了你` / `mentioned you` | 点进去回复。**回复时同时读两条内容**：我的原帖（上下文）+ 他具体说了什么（要接住的点），生成对话式回应 |
| **别人关注我** | `followed you` / `关注了你` | 点**这个人的**头像进主页（聚合卡片里有多个头像时按 handle 精确匹配，不会点错人），走「翻 10 条 + 随机互动 3~5 篇 + 关注」；处理完**回通知页**继续下一条；已关注过的跳过 |

> **通知阶段默认开启**（`notif_enabled: true`）。通知列表是虚拟列表，进入后会先滚动加载多屏再收集，
> 否则底部的新粉丝读不到。回复类占会话前 20% 时间、关注类额外给到 40%，互不挤占。
| **别人点赞我的帖子** | `liked your post` / `喜欢了你的` | **不处理**，只计数写日志 |

其它类型（转发、系统通知）一律忽略。

## 关注限流（防封号，三道闸）

新号短时间大量关注是最容易被平台抓的行为。**任何关注路径**（详情页、发现页就地关注、
新粉丝主页、作者主页）都必须先过 `followAllowed()`：

| 闸门 | 默认 | 说明 |
|---|---|---|
| 两次关注间隔 | **60~180 秒随机** | 每次随机一个目标间隔，没到就不关注，日志写「距上次关注才 X 秒」 |
| 每小时上限 | **8 次** | 硬限流。新号建议 5~8；日志写「本小时已关注 X/8」 |
| 每日上限 | **25 次**（沿用 `max_follow`） | 达上限当天不再关注 |
| 单轮上限 | **5 次**（`follow_per_session`） | 一轮会话内最多关注几个 |

前三项在控制台「关注 / 发现」分组里都能调。所有关注成功都走 `noteFollow()` 统一记账，
不会出现某条路径绕过限流的情况。

## API 配置（存本地，不用每次填）

控制台「API 配置」卡片里填 Key / Base URL / 模型 → 点「保存 API 配置」。

- 存在 `chrome.storage.local` 的独立键 `xa_llm` 里，**下次打开自动带出**，
  只显示前 4 位 + 后 4 位（中间打码）。
- **留空保存 = 保持原值**，不会把已存的 Key 清掉；要清除请点「清除 Key」。
- 「保存设置」也改成**合并写入**——以前侧边栏和控制台字段不同，整体覆盖会互相
  抹掉对方保存的字段，这就是「Key 每次都要重填」的原因（已修）。
- 密钥只留在本机浏览器，除了发给你填的模型接口（api.deepseek.com 等）之外不发给任何地方。

## 评论规则窗口（独立页面）

控制台「评论规则」卡片 → **打开评论规则窗口**（`comment-rule.html`），一页看全、改全：

| 区块 | 内容 |
|---|---|
| 当前规则 | 「我的规则」/「原 SOP 规则」切换 |
| 触发条件 | 评论概率、概率上限、同一帖只回一次、重点领域关键词 |
| 字数与长度 | 目标字数（5~20，实际 ±5 随机，硬上限 20）、长度档（SOP 用） |
| 语气与风格 | 随和/专业/幽默/好奇/共情/直接 |
| **提示词** | 整段 system 提示词，可直接编辑；支持占位符 `{len} {lo} {hi} {cap} {tone} {post}`，点占位符标签插入到光标处；可一键恢复默认 |
| **模板句** | 没配 Key 时用的短句池，一行一句，`{p}` 自动替换成原帖短语；显示条数和「哪些没带 {p}」 |
| **实时预览** | 用示例帖子模拟生成 6 条，显示每条字数和是否超 20 字 —— 不调用模型 |

保存写回 `xa_settings`（同样合并写入），**下一轮会话生效**。

## 自动注入（2026-11-18 改：不再需要手动点）

「注入页面」按钮只对**当前那个 x.com 标签页**做一次性注入，这是以前要反复手点的根源。
现在注入全自动，三层兜底（都幂等，content.js 有 `__XA_LOADED__` 守卫）：

1. **manifest 声明**：任何 x.com 页面加载时自动注入（浏览器原生机制）。
2. **标签页加载完成兜底**：background 监听 `tabs.onUpdated`，x.com 加载完成补一次。
3. **扩展重载/更新/浏览器启动兜底**：`onInstalled` / `onStartup` 时把所有已开着的
   x.com 标签页全部补注入（扩展重载后旧页面里的脚本上下文会失效，这是以前
   「要一直点注入」的真正原因）；控制台发现未注入也会自动补，不再提示手点。

注入后脚本驻留页面：**滚动、点进帖子、返回都不需要重新注入**（X 是单页应用，
不换文档）。控制台「重新注入」按钮仅作极端情况的手动兜底。

侧边栏（panel）保留作轻量入口，里面「控制台」按钮也能打开这个窗口。

## 安装（Edge，和现有调试浏览器互不干扰）

1. 地址栏开 `edge://extensions`（Chrome 是 `chrome://extensions`）
2. 打开右下角「开发人员模式」
3. 「加载解压缩的扩展」→ 选 `extension/` 目录
4. 打开 x.com 登录小号 → 点工具栏图标开侧边栏
5. 「开始一轮会话」手动跑一轮；「循环：开」= 每 30 分钟自动开一轮 30 分钟首页时间线
6. 面板里填 LLM Key（DeepSeek）；不填就模板兜底，一样过 SOP 校验

## 已知边界（诚实记录）

- **慢网加载监控（2026-11-18 加）**：网速慢时 DOM 分批渲染，「点了就动」会打在
  旧页面上。现在所有导航/切栏目/滚动/进详情后都有等待：转圈（`[role=progressbar]`，
  排除视频音量条）消失 + 帖子数量连续两次轮询稳定 + 内容签名真的变化，才继续。
  滚动后额外等新帖追加；连续 3 次滚动没新帖 = 到头或加载不出，滑回顶部等下一轮。
  等待超时会写日志并「按当前状态继续」，不会死等卡住会话。
- **实时视窗**：控制面板顶部卡片显示当前正在读的帖子（作者/领域标签/正文摘要），
  下面是一条 280px 高、**可上下滑动**的历史活动区，保留全部活动记录（最多 300 条），
  按动作**分色显示**，贴底时自动跟随最新一条；往上翻历史时不会被强行拉回底部。
- **活动日志结构化（2026-11-18）**：`activity` 每条新增 `kind` 字段（read/judge/like/cmt/
  follow/skip/fail/nav/wait/info），由 `logAct(msg, kind)` 显式传入，老调用点由 `guessKind()`
  按文案兜底推断。UI 的颜色、筛选、统计下钻全部依赖这个字段，**别再用文案匹配做分类**。
- **不碰自己的帖子（2026-11-18 加，硬规则）**：选帖时就把 `handle === 我` 的帖子/回复
  过滤掉——不点进去、不赞、不评。详情页、通知回复、作者主页三条路径各有独立兜底检查。
  之前漏了这层，导致在自己的回复下面连续回复自己 3~4 次（号自己跟自己对话，平台最容易
  判定刷量）。整屏都是自己的帖子会自动往下翻，连续 4 屏仍全是则回顶部拉新一批。
  读不到自己的账号名时会在日志里**显式告警**，不会静默失效。
- **时间线刷新（2026-11-18 改）**：优先点顶部的 **「Show N posts」** 按钮或蓝色
  「新帖」箭头拉新帖（真人就是这么做的），没有按钮才滚回顶部。并且加了门槛
  ——**本轮读满 `min_read_before_refresh`（默认 12）篇之前不回顶刷新**，
  避免反复刷同几条帖子。日志会写「本轮才读 X/12 篇 —— 继续往下翻，先不刷新」。
- **时间线无限流处理**：X 的时间线新帖在上方，一直往下滑会滑进旧帖区。现在的策略：
  ① 滚动后先等新帖追加（最多 20 秒，慢网分页请求晚到是常态）；② 连续两轮滚动都没有
  新帖且已读够篇数 → 点「Show N posts」/「新帖」箭头回顶拉新，没有则滚轮回到顶部；
  ③ 仍然没变化就停 8~15 秒再继续，不会死循环卡住。滑过自己的帖子也算一次滚动。
- **全文记录（2026-11-18 改）**：之前正文只截 400 字；现在 `readTweets` 读**整条正文**，
  卡片里折叠的长文（Show more）会先展开再判定，留档写的是全文，日志会标注「全文 N 字」、
  展开成功时提示「展开长文：X → Y 字」。注意：X 的详情页本身不折叠，时间线折叠的
  长文只有真点开「显示更多」才能拿全——程序现在会替你点这一下。
- **发现页找人**：首页每读 5 篇去一次发现页（Explore），收集页面上出现的可关注用户。
  `explore_prob`（默认 0.5，面板可调）的含义是：**未关注的用户里，有多大概率点进主页
  浏览 10 条 + 随机互动 3~5 篇 + 关注**；**没命中的不是跳过，而是直接在那一行点关注**
  （不进主页），把关注量做起来。两者都受 `max_follow` 每日上限约束。
- **开始前先刷新（2026-11-18 加）**：`startSession()` 会先点「Show N posts」/「新帖」
  按钮拉最新一批；没有按钮就滚到顶再点一次首页 tab 触发重载。
- **会话统计实时（2026-11-18 加）**：以前只在阶段切换时同步，读帖期间控制台数字是冻的。
  现在 `startStatsSync()` 每 1.5 秒把 stats/phase/now 快照写进 storage，`stopSession()` 清理定时器。
- **重点领域加权**：股市 / AI / 半导体 / 经济 命中的帖子质量分 +2、赞评概率各 +0.15；
  互动帖（回复我、向我提问）即使内容薄也允许回。看到的所有帖子都按概率摇赞/摇评，
  主动多互动做权重（2026-11-18：短帖 ≥10 字且命中重点领域也放行评论；评论概率默认
  提到 0.85）。要评论就自动点进详情页。
- **关注（2026-11-18 改：先翻主页互动再关注，不判方向）**：详情页右侧 Relevant People
  直接读关注态（Follow/Following），不必为「查看」而点进主页。未关注 → 进其主页
  **浏览 10 条帖子（不够就滚动加载，逐条读全文）→ 随机抽 3~5 篇、每篇随机赞或评**
  → 最后**直接关注**（用户策略：不看方向/质量，涨互动、涨时间线）。关注成功以按钮
  翻成已关注态为准；主栏范围查按钮，避免把右侧「Who to follow」别人的按钮当成作者的。
  单会话关注上限默认 5，每日上限 max_follow 仍守住。
- **落点校验（2026-11-18 加）**：`getBoundingClientRect` 给的 CSS 坐标和 CDP
  `Input.dispatchMouseEvent` 的实际落点之间可能有系统性偏差（页面缩放、时间线
  自动滚动、窗口状态都会引入）。第一版没校验就点 → 表现为「反复在一个空点上
  点了又退、退了又点」。现在每次点击前先把鼠标移过去、检查目标元素是否进入
  `:hover`，不中就按由近及远扫描修正（±24px），并累计学习全局偏移；会话开始
  还会用导航锚点先标定一次。**如果标签页不可见导致 `:hover` 永远不亮，连续
  3 次失败后自动退回直点模式**（日志会说明）。要校验全程有效，x.com 标签页
  保持可见（可以是活动标签页，窗口不必前台）。
- **速度系数**：面板「速度系数」默认 1.5（= 比第一版慢一半）。它作用于移动、
  悬停、按压、滚动间隔和所有阅读停顿；打字仍由「打字 ms/字」单独控制（默认
  130 不动）；提交后的证据轮询不乘系数（那是等服务器，不是人的节奏）。
- **首页 Feed 栏目策略（2026-11-18 改）**：默认在「**为你推荐**」刷；连续两次刷新都拉不出新帖

  「为你推荐」，两个栏目来回换着找内容。切换后清空「已读过」记录与读帖计数（两个栏目的内容不同）。
  栏目识别同时认中英文（`为你推荐/For You`、`正在关注/Following`），切之前会先看当前选中的
  是哪个，已经对了就不重复点击（切栏目会触发时间线重载，能省则省）。

  alarm 唤醒 background 是 Chrome 官方机制，可靠。

## 定时自动执行（随机间隔 + 随机时长）

在控制台「定时自动执行」卡片里配置。**两个维度都随机，不固定任何时间点**：

| 参数 | 含义 | 默认 |
|---|---|---|
| 间隔最短 / 最长 | 每轮结束后在区间内**随机抽**一个值，决定多久后开下一轮 | 40 ~ 110 分钟 |
| 本轮时长 | 每轮跑多久也在区间内随机抽 | 18 ~ 45 分钟 |
| 夜间安静 | 这段时间不执行（如 1 点到 8 点） | 1 ~ 8 点 |
| 最多跑几轮 | 0 = 不限 | 0 |
| 真随机 | 关掉则用区间中点固定值 | 开 |

**间隔从「上一轮结束」开始算**，不是从开始算。这样会话时长变化不会污染间隔。

举个栗子🌰，某天的实际排程：

```
第1轮  20:00 开始 → 跑 19 分 → 20:19 结束
        间隔  53 分 → 下次 21:12
第2轮  21:31 开始 → 跑 24 分 → 21:55 结束
        间隔  91 分 → 下次 23:26
第3轮  23:50 开始 → 跑 39 分 → 00:29 结束
        间隔  68 分 → 下次 08:34（避让夜间，推到次日早上）
```

**为什么必须两处都随机**：固定间隔（每 30 分钟整）和固定时长（每次 30 分钟）在平台侧看
就是脚本特征——时间方差接近 0，人做不到。真正像人的作息是：有时刷 20 分钟，有时 40 分钟；
有时一小时后回来，有时两小时后。

**前提**：浏览器要开着，且有 x.com 标签页。没有标签页时会记录「跳过」并继续排下一轮，不会中断计划。
浏览器重启后自动恢复排程（`resumeAuto()`）。

## 评论为什么会雷同（排查指南）

**评论来源有两种，日志里现在会标明**：

| 日志标记 | 含义 |
|---|---|
| `模型 deepseek-flash` | 模型生成，正常 |
| `模型 xxx（第 2 次才过）` | 第一次没通过校验，重试后成功 |
| `⚠ 模板降级（模型没给出合格句子）` | **模型三次都失败，退回了固定模板池** |

**模板池是死句子**（几十条），一旦大量降级，评论就明显千篇一律。看到 `⚠ 模板降级` 频繁出现，
说明模型一直给不出合格句子 —— 通常是提示词有问题，不是模型不行。

### 坑一：设置里存着旧版聊天助手模板

以前存过 `你是即时通讯回复助手……附和……像真人在聊天软件里发消息` 这类提示词，
它会**覆盖代码默认值**，导致：

- 结构固定（认同 + 附和 + 提建议），每条都一样
- 当聊天软件用，没有公开评论的立场
- 写死 40 字，长度也整齐

会话开始时日志会提示：
`评论提示词：⚠ 用的是设置里存的自定义提示词` + `⚠ 检测到旧版聊天助手模板`。

**解决办法**：评论规则窗口 → 提示词 → 选内置默认，或粘贴新的正式号提示词。

### 坑二：没有句式轮换

即使提示词写得好，模型也倾向用同一个安全句式。
现在由**代码指派切入角度**，8 种（直接判断/条件句/反面情况/具体细节/个人偏好/提问/不同意/代价），
避开最近 3 次用过的，保证任意连续 4 条内不重复。

提示词里也会带上 `【这一条的切入方式】`，强制模型换开头。

## 读到过的帖子自动存本地

运行时会读大量帖子（时间线、发现页、作者主页、通知页），**读到的全部自动留档**，
不需要手动保存。

| 存储 | 存什么 | 数量 |
|---|---|---|
| `xa_state.seenTweets` | 运行时**读到**的帖子（按 ID 去重，记首次/最近读到时间、读到次数） | 上限 3000 |
| `xa_state.records` | **处理过**的帖子（带动作标记：赞/评/跳过原因） | 上限 2000 |

`readTweets()` 里统一存档，所以所有读帖路径都覆盖，不用在每个调用点各写一遍。
存档是**异步后台动作**，不 await，不影响刷帖节奏。

过滤规则：没有 ID 的不存（从发现页直接进主页那种）、正文不足 10 字的不存（纯图/纯链接）。

**用途**：「评论规则」窗口的「用真实帖子试效果」直接读这份数据，
跑一轮会话就能积累几十条真实样本，比内置的 8 条样本准得多。

控制台「帖子留档」页会显示 `本地已存 N 条读到的帖子`。

## 栏目只认「为你推荐」和「正在关注」

X 顶部除了这两个，用户自己还能加「AI」「创业公司」「商业」「加密」「股票」等栏目。
**这些一律不碰**。

### 三个机制

**① 选择器只认精确文案**

`switchFeedTab` 只匹配 `为你推荐 / 正在关注`（含英文 For you / Following）。
以前有个「包含匹配」兜底，会误选中「创业公司」（因为它也在那一排），这个兜底已经删掉。
找不到目标栏目就放弃切换，**绝不去点别的栏目**。

**② 点击前二次确认**

点之前再校一次目标文案，不是目标就不点，并记日志 `拒绝点击：目标栏目是「X」，不是「为你推荐」`。

**③ 栏目守卫（每 1.5 秒）**

只要当前选中的栏目不是那两个字之一，立刻拉回「为你推荐」：

```
⚠ 当前停在「创业公司」栏目（不在允许范围）→ 拉回「为你推荐」
```

连续 3 次拉不回就整页回首页（`goHome()`）。

### 比例轮换（默认 7:3）

| 设置 | 含义 | 默认 |
|---|---|---|
| 推荐 : 关注 | 「为你推荐」占比，界面填百分比 | 70（即 7:3） |
| 每读几篇换一次 | 一个栏目停留的基准篇数 | 7 |

用**配额制**，不是每次掷骰子。原因：只有两个栏目时，每次独立掷骰子会让切换序列变成
`关推关推关推`——因为不进这个就进那个，看着像完美交替，反而更假。

配额制每轮抽「去哪 + 待几篇」（基准 ±50% 抖动，上限 12），序列呈块状：

```
推荐7篇  关注9篇  推荐6篇  关注4篇  推荐8篇  关注11篇 …
```

实测 3000 篇：7:3 设置下实际 70% / 30%，比例准，顺序无规律。

## 已修的严重 bug：点栏目时长按

`inputPress` 的 `mousePressed` 曾写成 `modifiers: 1`（= Ctrl 修饰键），
等于 **Ctrl+左键**，被 X 当成右键/长按，弹出「管理时间线 / 移除创业公司」菜单。

现在鼠标事件的 `modifiers` 全部为 `0`，按压时长 60~160ms（太久也会被当长按）。

## 没有帖子时：双击「主页」刷新

用户明确要求：**没帖子就双击左侧栏「主页」**，单击只是回到顶部，双击才会重新加载时间线。

`refreshOrTop` 的顺序改成：

| 顺序 | 动作 | 说明 |
|---|---|---|
| ① | **双击左侧栏「主页」** | 首选，最接近真人（没内容了双击主页签重载） |
| ② | 点「Show N posts」/「新帖」按钮 | 横幅上那颗按钮 |
| ③ | 往下滑 | 老内容可能还没翻完 |

以前是「先死命往下滑 8 次」才回头看按钮，用户看到的就是卡住不动。

**技术要点**：双击必须走 `background.js` 的 `dblclick` 原语，不能在 content 里连调两次
`clickEl`——那会重新 hover 和落点校验，鼠标一移动浏览器就当成两次独立单击，双击事件不触发。

`inputDoubleClick` 的实现：同坐标连按两次，`clickCount` 依次 1、2，间隔 60~140ms，
**中间不发任何 `mouseMoved`**。实测两次按下间隔约 171ms（阈值 500ms 以内），会被正确识别。

## 三道基础检查（可单独开关）

模型生成评论时，除了可选的「发送前审核」，还有三道**默认全开**的硬门槛，控制生成时会不会让这条过。主控制台「评论规则」卡片和侧边栏「评论审核」折叠区都能单独开关：

|---|---|---|
| ① 基本校验 | 空评论 / 纯符号 / <4字 / 互关互赞 | 这些也能发 |
| ② 身份检查 | 作者做的事不能当成自己的说（复述） | 复述也能发 |
| ③ 观点检查 | 要有观点/态度/提问；纯附和算废话 | 说得好/学到了 这类也能发 |

- 存储字段 `xa_settings.check_validate` / `check_echo` / `check_opinion`
- 默认全开，只有存了显式 `false` 才关（和审核开关不同，那些默认关）
- 关掉任意一道，模型重试时的重写理由也会跳过对应检查，不会无限重试
- 和「发送前审核」是两层：审核是发送前打分（默认关），这三道是生成时把关（默认开）

## 发现页（探索）不该反复进，没新帖就双击主页

### 问题：经常自动点进左侧「探索」，然后卡在体育/趋势组件上

X 的 /explore 默认显示的是**趋势、新闻、体育比分**这类组件，**很多时候一条帖子都没有**。
旧逻辑等帖子等满 25 秒才判定失败，失败后回主页，过 5 篇阅读又进一次 → 无限循环。

现在的处理：

| 改动 | 说明 |
|---|---|
| 等帖时间 25s → **9s** | 发现页本来就没帖子，再多等也是白等 |
| 失败后标记 `exploreBlocked` | **20 分钟内不再进发现页**，避免来回乒乓 |
| 失败后**双击主页** | 不是单击跳转，是双击重新拉时间线（和下面刷新同一套动作） |

### 问题：不会自动刷新出新帖

主页「这一屏全是读过的帖子」时，代码按**从轻到重**三级处理：

| 顺序 | 动作 | 什么时候用 |
|---|---|---|
| ① | 往下滚一屏（等 10s） | 多数情况只是分页慢 |
| ② | 点横幅「Show N posts」 | 有那颗按钮时，最不打扰 |
| ③ | **双击左侧栏「主页」** | 前两步都不行 → 真正重新拉时间线 |

- 读不够 `min_read_before_refresh`（默认 12）篇时，最多再翻一屏，**不会频繁刷新**
- 双击后等主页加载 20 秒，再从头走流程
- `doubleClickNav` 走 CDP 同坐标连按两次（`clickCount` 1→2，间隔 60~140ms，中间不移动鼠标），否则浏览器会当成两次独立单击，双击事件不触发

## 事故修复：模型把「思考过程」当评论发出去

### 事故现场

日志里出现过这样的评论：

```
评论：用户需要我针对这个帖子写一条评论，评论要用中文，长度16字左右，语气共情，
直接给出判断，上来就说看法，不要先肯定对方。帖子内容是问大家第一次用AI是哪个大模型…
```

这是模型的**思考过程**被当成了评论发出去。根因是上一版为了让「content 为空」的推理型模型也能出结果，
把 `reasoning_content` 兜底当成了回答 —— 这是严重设计错误。

### 三层修复

| 层 | 做法 |
|---|---|
| 1. background.js | **彻底不再使用** `reasoning_content` / `reasoning` 作为回答。`content` 为空就直接报错，由上层加大 token 重试（900 → 2400） |
| 2. comment.js `looksLikeThinking` | 输出里出现「用户需要我 / 帖子内容是 / 角度要换 / 评论要用 / 要求：」等特征 ≥2 个 → 判为思考过程，要求模型重写只输出评论本身 |
| 3. 提示词 | 明确写「只输出评论本身，不要输出思考过程，第一行字必须是评论」 |

第 2 层**不受任何开关控制**，永远生效 —— 这是事故防线，不是质量选项。

### 实测

| 输入 | 结果 |
|---|---|
| 事故原文 | ✓ 拦下，不会发出 |
| 5 条正常评论 | ✓ 全部放行，无误杀 |
| 第一次输出思考、第二次正常 | ✓ 自动重写成功（attempts=2） |
| 三次都是思考 | ✓ 这条跳过，一条不发 |

## 修复：「显示 175 帖子」按钮没被认出来

中文界面的横幅按钮是 **「显示 175 帖子」**，旧正则只匹配 `显示 N 条`，
所以中文站点上这颗按钮一直没被识别，导致「没新帖」时不会去点它。

现在匹配：`显示 175 帖子` / `显示 12 条` / `显示 175 个帖子` / `Show 175 posts` / `新帖子` / `已发布`。
验证过不会误认「首页」「为你推荐」「正在关注」。

没新帖时的顺序：滚一屏 → **点「显示 N 帖子」** → 双击主页。

## 修复：点「主页」却点进「探索」

### 原因

侧栏各项上下紧挨着（主页 / 探索 只隔约 48px）。通用点击函数 `clickEl` 会带上一个
**全局累积偏移** `_off.dy`——这个偏移本来是给时间线里的帖子做落点标定的。
一旦 `:hover` 校验失效（标签页在后台时 `:hover` 永远不亮，系统会退回"直点模式"），
这个偏移就把落点整体下移，**正好压到下面的「探索」**。

### 修法

导航和栏目改用**几何命中校验**（`clickExact` / `clickNavExact`）：

- **完全不用** `_off` 偏移
- 点击前用 `document.elementFromPoint(x, y)` 验证：那个点必须落在这个元素（或它的子孙）上
- 只允许在元素矩形内部上下左右试 3 / 6 / 10px，**绝不越界**（越界就可能点到隔壁）
- 校验不过就跳过这次点击并记日志，宁可不动也不点错

栏目 tab 也换成同一套（`为你推荐` 和 `创业公司` 横向紧挨着，同样是偏移重灾区）。

## 修复：「显示 N 帖子」要在进栏目时就先点

按用户要求，遇到以下时机都先找这颗按钮：

| 时机 | 行为 |
|---|---|
| 进入/回到时间线 | 先滚到顶部，有「显示 N 帖子」就点（最多 3 分钟查一次，避免打断阅读） |
| 刚切换栏目后 | 时间线是重新拉取的，再查一次 |
| 运行时遇到看过的帖子 | **先拉到最上面**查「显示 N 帖子」→ 没有再往下滚 → 再查一次 → 都没有才双击主页 |

为什么要先拉回顶部：新帖是插在时间线**顶部**的，往下滚只会越走越旧。

## 从活动日志定位到的死循环（2026-11-24）

### 日志现场

```
[01:26:42] ⚠ 当前停在「创业公司」栏目（不在允许范围）→ 拉回「为你推荐」
[01:26:42] 切栏目：点击「为你推荐」
[01:26:43] 遇到看过的帖子 → 发现顶部「查看新帖子」，点它拉新帖
[01:26:44] 为你推荐 栏目加载较慢，继续等待渲染…（当前 6 条）
[01:26:46] ⚠ 当前停在「创业公司」栏目 → 拉回「为你推荐」   ← 1.5 秒后又是它
…
[01:27:05] 已切到「为你推荐」栏目（内容已更新）  ×5 条连发
```

### 三个叠加的 bug

**① 栏目守卫没有防重入（主因）**

`checkFeedTab` 每 1.5 秒跑一次，但它调用的 `switchFeedTab` 内部要等 25 秒内容渲染。
调用方不 await，所以每 1.5 秒就**并发**启动一次切换 → 点击风暴 → 时间线一直在重载，
永远读不到帖子。日志里 1-2 秒一条的「切栏目」就是这么来的。

**② `pageLoading()` 把隐藏的转圈也算成"正在加载"**

`document.querySelector('[role="progressbar"]:not([aria-valuenow"])`
只要 DOM 里有转圈节点就返回 true。X 会保留隐藏的转圈占位，
于是 `waitContent` **每次都等满 25 秒超时**——这就是为什么"整体很卡、什么都做不成"。

**③ 点「查看新帖子」只重渲染，没有新内容**

以前用 DOM 签名判断成功，点一下整列重渲染签名必变 → 误判成功 → 过两秒又点一次。
实际上还是那 6 条帖子。

### 修法

| 问题 | 修法 |
|---|---|
| 并发切换 | `feedFixBusy` 防重入锁 + 8 秒冷却；连续 3 次纠不回来 → **硬导航 /home**（X 默认就是为你推荐），不再无限试 |
| 转圈误判 | `pageLoading` 改成**只认可见**的转圈（尺寸 ≥8px 且在视口内） |
| 拉新帖误判 | 改用**帖子 id** 判断：点完必须出现「不在读过的 seen 里」的新 id 才算成功；同一颗按钮 45 秒内不重点 |
| 双击刷新太频繁 | 60 秒内最多刷一次 |

### 效果（模拟 120 秒）

| 版本 | 提交换栏目次数 |
|---|---|
| 修复前 | 约 80 次（每 1.5 秒并发） |
| 修复后 | 6 次串行 + 1 次硬归位 |

## 「显示 35 帖子」在哪、怎么点

位置：**发帖框下面、第一条帖子上面**那一行文字（X 中文版就是「显示 35 帖子」）。

以前找不到它的原因：`findNewPostsPill` 只扫描 `button` 和 `div[role="button"]`，
而这一行很可能是普通 `div`/`span`，靠父层接点击，所以**从来没被认出来**。

现在两级查找：

1. 先在天然可点击元素里找（`button` / `[role=button]`）
2. 找不到就扫任意 `div`/`span`/`p` 的文本，然后**向上找 6 层**里第一个可点击祖先
   （`button` / `role=button` / 带 `tabindex` 的容器）

文案白名单（中英文全覆盖）：

| 认得的 | 不认得的（验证过不误点） |
|---|---|
| 显示 35 帖子 / 显示 175 帖子 / 显示 12 条 / 显示 175 个帖子 | 发帖 / 有什么新鲜事？ |
| 查看新帖子 / 新帖子 / 已发布 / 已推送 | 为你推荐 / 正在关注 |
| Show 175 posts / 175 posts / New posts | 显示更多 / 搜索 / 主页 |

## 点击校验全面改为几何命中

以前点击靠 CSS `:hover` 判断落点对不对。但**标签页在后台时 `:hover` 永远不亮**，
系统连错 3 次就退回「直点模式」——完全不校验，带着累积偏移盲点，
于是「主页」点到「探索」、「为你推荐」点到「创业公司」。

现在全部改用 `document.elementFromPoint(x, y)`：

- 落点必须真的在这个元素（或子孙）上，否则不点
- 不依赖 `:hover`，后台标签页也准确
- 只允许在元素矩形**内部**小范围调整（最多到边框内 2px），绝不越界
- 校验不过就跳过并记日志：`落点校验失败：鼠标移不到目标上`

落点标定也简化了：不再用 `:hover` 探针（那套会打出"退回直点模式"的误导日志），
偏移直接清零，每次点击逐次校验。

## 已删除：点「显示 35 帖子」按钮（用户决定）

### 为什么删

这颗按钮（发帖框下面、第一条帖子上面那行字）在中文界面上经常被**顶部固定栏遮挡**，
`elementFromPoint` 落点校验必然失败，日志反复刷：

```
[03:46:34] 落点校验失败：鼠标移不到目标上，跳过这次点击
[03:46:38] 落点校验失败：鼠标移不到目标上，跳过这次点击
[03:46:43] 落点校验失败：鼠标移不到目标上，跳过这次点击
```

而且点击失败时**没有设置冷却**（冷却只在点击成功后才设），
所以每个主循环都会重试一次，形成死循环。

### 现在怎么做

刷新一律**双击左侧栏「主页」**，不再找任何按钮：

| 时机 | 行为 |
|---|---|
| 这一屏没有新帖 | 滚回顶部 → 往下滚一屏看看 → **双击主页**（60 秒限流） |
| 整屏都是自己的帖子 | `refreshOrTop` → **双击主页** → 再往下滑找老内容 |
| 强制刷新 | `hardRefreshTimeline` → 滚到顶 → **双击主页** |

已删除的函数：`findNewPostsPill`、`clickNewPostsPillIfAny`（只留注释说明为什么删）。

### 落点校验失败日志也改了

现在会说清"那个位置实际被谁占着"，方便判断是遮挡还是元素消失：

```
落点校验失败：目标中心实际是「搜索」，跳过这次点击
```

## 什么时候双击主页（最终版）

用户明确：**看到自己的回复、或者看到看过的帖子 → 直接双击主页更新。**

| 触发情况 | 判定 | 动作 |
|---|---|---|
| **看到自己的回复** | 这一屏里自己的 ≥ 别人的 | 双击主页换一批（60 秒限流） |
| **看到看过的帖子** | 这一屏没有一条是没读过的 | 滚回顶 → 往下滚一屏 → 双击主页（60 秒限流） |
| 整屏都是自己的帖子 | `hardRefreshTimeline` | 双击主页 |
| 发现页没有帖子 | 趋势/体育组件 | 双击主页 + 20 分钟内不再进发现页 |

### 和之前的差别

| | 旧 | 新 |
|---|---|---|
| 看到自己的 | 要**连续 4 屏**都是自己的才刷新 | 自己的 ≥ 别人的就换（少数自己的照常读，不浪费） |
| 看到看过的 | 要**读够 12 篇**（`min_read_before_refresh`）才刷新 | 直接换，不用等门槛 |

`min_read_before_refresh` 这个设置项保留在设置里，但**不再拦刷新**。

### 限流

所有双击刷新共用 `ctx.dblLastAt`，**60 秒内只刷一次**。
不限流的话会变成"刷 → 读 → 还是自己的/看过的 → 再刷"的高频循环，
平台侧看就是异常刷新行为。
