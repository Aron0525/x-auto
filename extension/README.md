# 浏览器插件版（X Auto SOP Extension）

Python 版的「同门」：同一套 SOP 判定与评论生成逻辑移植成 MV3 扩展，
不再依赖调试端口和 SendInput，装进 Edge/Chrome 就能跑。

## 与 Python 版的分工

| | Python 版（`xauto/`） | 插件版（`extension/`） |
|---|---|---|
| 输入方式 | Win32 SendInput（真实鼠标键盘，需要前台） | CDP `Input.dispatch*`（chrome.debugger，可信事件，**不需要前台**） |
| 会话循环 | 子进程 + UI 控制台 | content script 状态机 + sessionStorage 跨导航恢复 |
| 调度 | UI server / x_repeat | `chrome.alarms`：每 30 分钟自动开一轮 30 分钟会话 |
| SOP 判定 | `xauto/sop.py` | `extension/sop.js`（逐条移植，规则一致） |
| 评论生成 | `xauto/comment.py` | `extension/comment.js`（同一套 prompt/模板/校验） |
| 留档 | `data/tweets.jsonl` | `chrome.storage.local`，面板一键导出 JSON |

## 文件结构

```
extension/
  manifest.json    MV3：debugger/storage/tabs/scripting/sidePanel/alarms
  sop.js           SOP 判定层（跳过/质量分/展开/赞/评/校验/关注/通知）
  comment.js       评论生成（LLM 经 background 代发；无密钥走模板兜底）
  content.js       页面操作 + 会话状态机（home→detail→profile→notif）
  background.js    CDP 拟人输入（贝塞尔分步移动/逐字 130ms/滚轮 120 单位）+ LLM 代发 + 轮次 alarm
  dashboard.html/js 使用窗口（点工具栏图标打开）：控制面板/帖子留档/活动日志/使用说明 四页签，
                   今日额度进度条、会话统计、留档筛选表格、修复页面注入、导出记录
  panel.html/js    侧边栏（轻量入口：开始/停止/循环/参数 + 跳控制台）
```

## 使用窗口（dashboard）

点浏览器工具栏的扩展图标 → 弹出独立控制台窗口（1180×860）：

- **控制面板**：开始/停止/循环；行为参数（会话分钟、打字 ms、四个概率、关注上限、语气/长度档、
  是否处理通知）；LLM Key 与每日上限；今日额度进度条（到上限变红）；当前会话统计（读/展开/赞/评/藏/关注/滑过）
- **帖子留档**：表格浏览全部留档记录（时间/作者可点回原帖/内容/动作徽章），支持关键词筛选
- **活动日志**：滚动实时日志（content 的 logAct 全走这里）
- **使用说明**：30 秒上手 + SOP 规则摘要 + 故障处理速查
- 维护按钮：**修复页面注入**（`chrome.scripting.executeScript` 重放 sop/comment/content 三件套，
  解决「标签页比插件先开」或「刚重载过扩展」导致 content 不在的情况）、导出全部记录 JSON

侧边栏（panel）保留作轻量入口，里面「控制台」按钮也能打开这个窗口。

## 安装（Edge，和现有调试浏览器互不干扰）

1. 地址栏开 `edge://extensions`（Chrome 是 `chrome://extensions`）
2. 打开右下角「开发人员模式」
3. 「加载解压缩的扩展」→ 选 `extension/` 目录
4. 打开 x.com 登录小号 → 点工具栏图标开侧边栏
5. 「开始一轮会话」手动跑一轮；「循环：开」= 每 30 分钟自动开一轮 30 分钟首页时间线
6. 面板里填 LLM Key（DeepSeek）；不填就模板兜底，一样过 SOP 校验

## 已知边界（诚实记录）

- **慢网加载监控（2026-11-18 加）**：网速慢时 DOM 分批渲染，「点了就动」会打在
  旧页面上。现在所有导航/切栏目/滚动/进详情后都有等待：转圈（`[role=progressbar]`，
  排除视频音量条）消失 + 帖子数量连续两次轮询稳定 + 内容签名真的变化，才继续。
  滚动后额外等新帖追加；连续 3 次滚动没新帖 = 到头或加载不出，滑回顶部等下一轮。
  等待超时会写日志并「按当前状态继续」，不会死等卡住会话。
- **实时视窗**：控制面板顶部卡片显示当前正在读的帖子（作者/领域标签/正文摘要）
  和最近 3 条活动；每读到一帖、每次判定（赞/评/为什么不）都会写进活动日志，
  反馈动作（评论全文、关注理由）进帖子留档。
- **重点领域加权**：股市 / AI / 半导体 / 经济 命中的帖子质量分 +2、赞评概率各 +0.15；
  互动帖（回复我、向我提问）即使内容薄也允许回。看到的所有帖子都按概率摇赞/摇评，
  要评论就自动点进详情页。
- **关注**：点进详情页的帖子，作者若未关注 → 进其主页，看简介和近期内容再决定
  （SOP：不盲关）。关注成功以按钮翻成已关注态为准。
- **落点校验（2026-11-18 加）**：`getBoundingClientRect` 给的 CSS 坐标和 CDP
  `Input.dispatchMouseEvent` 的实际落点之间可能有系统性偏差（页面缩放、时间线
  自动滚动、窗口状态都会引入）。第一版没校验就点 → 表现为「反复在一个空点上
  点了又退、退了又点」。现在每次点击前先把鼠标移过去、检查目标元素是否进入
  `:hover`，不中就按由近及远扫描修正（±24px），并累计学习全局偏移；会话开始
  还会用导航锚点先标定一次。**如果标签页不可见导致 `:hover` 永远不亮，连续
  3 次失败后自动退回直点模式**（日志会说明）。要校验全程有效，x.com 标签页
  保持可见（可以是活动标签页，窗口不必前台）。
- **速度系数**：面板「速度系数」默认 1.5（= 比第一版慢一半）。它作用于移动、
  悬停、按压、滚动间隔和所有阅读停顿；打字仍由「打字 ms/字」单独控制（默认
  130 不动）；提交后的证据轮询不乘系数（那是等服务器，不是人的节奏）。
- **首页 Feed 选择**：面板可选 For You / Following，默认 For You；通知阶段跑完
  回首页沿用同一选择，不会偷偷切到 Following。
- CDP 事件可信但没有 OS 级轨迹：贝塞尔移动是逐点 `mouseMoved` 模拟的，
  比 SendInput 差一档（不带真实硬件时序抖动）。风险等级：介于合成事件和真实键鼠之间。
- 页面必须保持打开（可以后台标签页，不用前台）；**别关那个标签页**，会话状态在 sessionStorage。
- 调试横幅（"正在调试此浏览器"）是 chrome.debugger 的正常表现，X 页面看不到它。
- 同机如果 Python 版也在操作同一个 x.com 标签页，会互相抢焦点——二选一跑。
- Service Worker 30 秒空闲会被回收，但会话循环跑在 content 里不受影响；
  alarm 唤醒 background 是 Chrome 官方机制，可靠。
