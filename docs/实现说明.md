# X / 推特自动化 · 实现说明

> 复用 `boss-auto-greet` 项目已有的浏览器层（裸 CDP + 拟人输入），只新增 X 这一层的页面对象与命令。
> 端口 **9234**、独立 profile `C:\x-edge-9234`，与 BOSS 的 9222/9223 完全隔离。
> 全程没有任何 Playwright / Selenium —— 只有 `Runtime.evaluate` 读、`Input.*` 写。

## 一、分层

```
tools/x_launch.py     拉起/复用 9234 实例（独立 profile，可重入）
tools/x_probe.py      探针：看 DOM、看时间线、截图（选择器不靠猜）
tools/x_post.py       功能① 发帖（含 --verify 核对、--delete 清理）
tools/x_reply.py      功能② 读帖子并回复
tools/x_dm.py         功能③ 「我的消息」里回复

pages/x_twitter.py    X 页面对象（compose / reply / dm / mask 处理）
xauto/config.py       端口、profile、节奏、限额、选择器（一处改全局生效）
xauto/session.py      连 9234、找 x.com target、登录态判定、页内跳转
xauto/dom.py          等待/文本/滚动/截图等只读小工具
xauto/typing.py       拟人输入：IME 分块提交 + 逐字按键 + 缓动鼠标轨迹
xauto/store.py        去重簿（state.json）：已回过的 tweet / 会话

core/cdp.py           【复用】裸 CDP：只 Runtime.evaluate，绝不 *.enable
core/cdpinput.py      【复用】视口坐标换算（viewport_point / click_expr）
core/human.py         【复用】OS 级输入兜底（必要时）
```

## 二、三条硬约束

1. **只读走 `Runtime.evaluate`，绝不调 `*.enable`**
   X 的前端同样做调试指纹检测；一旦 enable 了 Runtime/Page/DOM 域，行为特征就变了。

2. **写操作走 `Input.*`，但必须是「拟人形态」**（见第六节）
   窗口必须「可见」（可被遮住，不能最小化），否则浏览器会丢弃输入事件。

3. **每次写入都做「发前校验 + 发后取证」**
   发前：读回编辑器内容，与预期逐字比对，不一致直接中止（宁可不发，不发错）。
   发后：编辑器清空 + toast + 帖子计数变化，至少拿到一项才算成功。

## 三、三个功能的调用方式

### ① 发帖

```bash
python tools/x_launch.py                          # 首次：起实例 + 手动登录一次
python tools/x_post.py --text "内容" --dry-run      # 只填不点（默认行为）
python tools/x_post.py --text "内容" --yes          # 真发，发完去主页核对
python tools/x_post.py --file post.txt --yes
python tools/x_post.py --verify                   # 只核对主页最新一条
python tools/x_post.py --delete "正文片段"          # 按片段在自己主页里找到并删除
```

链路：清浮层（含 mask）→ 复用页内发帖框 / 点左栏发帖（失败退回快捷键 `n`）
→ 清空编辑器（Ctrl+A + Backspace）→ IME 分块输入 → 读回校验
→ 等按钮 `aria-disabled` 转 false → 停 1.8~4.2s → 点发送 → 等编辑器清空 → 抓 toast。

### ② 读帖子并回复

```bash
python tools/x_reply.py --read -n 10                                   # 先看抓到什么
python tools/x_reply.py --url https://x.com/home --template "..." -n 3 --yes
python tools/x_reply.py --url "https://x.com/search?q=Agent&f=live" --keyword Agent -n 2 --yes
```

链路：目标页 → `wait_tweets()` 等渲染 → 抽 `article[data-testid="tweet"]`
→ 关键词过滤 + 去重簿过滤 → 限额裁剪 → 逐条打开详情页 → 检查有没有回复框
→ 填回复 → 校验 → 提交 → 取证 → 冷却 `ACTION_DELAY`。

### ③ 「我的消息」里回复

```bash
python tools/x_dm.py --list                     # 会话列表（含未读标记）
python tools/x_dm.py --read -n 3                # 看每个会话最后几条
python tools/x_dm.py --template "收到～" --unread-only -n 3 --yes
```

链路：打开 `/messages` → 抽会话列表 → 按未读/去重簿筛选 → 打开会话
→ 读最后几条消息判断上下文 → 往 `dmComposerTextInput` 输入 → 点发送 → 校验清空。

### ④ 首页刷帖 → 点进去 → 评论 + 点赞 → 返回继续

```bash
python tools/x_browse.py                          # 刷一轮，看会挑中什么（默认不写）
python tools/x_browse.py --scroll 6 --picks 2     # 刷 6 屏、深看 2 条（不写）
python tools/x_browse.py --yes --picks 1          # 真跑：评论 + 点赞
python tools/x_browse.py --yes --no-reply         # 只点赞
python tools/x_browse.py --yes --no-inline-like   # 只在详情页点赞，不在信息流里顺手点
```

模拟真人的动作序列：

```
回家页 → 刷几屏（距离随机、偶尔停下来多看一会儿）
      → 顺手给 0~2 条感兴趣的点红心（信息流里的 ❤️，不点进去）
      → 挑 1 条：点正文进详情（SPA 路由，不整页刷新）
      → 读正文 → 生成评论 → 点赞 → 回到首页 → 继续刷
```

挑帖规则（`tools/x_browse.py` 里的 `filter_candidates`）：

| 条件 | 处理 |
|---|---|
| 正文 < 12 字（纯图/纯链接） | 跳过 |
| 转推/置顶/推荐标记（`socialContext`） | 跳过 |
| 自己的帖子 | 跳过 |
| 命中 `SKIP_KEYWORDS`（互关/抽奖/引流话术） | 跳过 |
| 命中 `RISK_KEYWORDS`（赌博/灰产/拉人头…） | 跳过 |
| 作者关了回复 | 跳过 |
| 已经评论或点过赞（去重簿） | 跳过 |

剩下的按「兴趣分」（`INTEREST_KEYWORDS` 命中数 + 随机量）排序，从前几名里随机挑。

**点赞有两个位置**，都支持：

- `like()` —— 详情页主帖的 ❤️（作用域锁定在第一条 `article`，不会点到楼下的回复上）
- `like_in_timeline()` —— 首页信息流里那一条的 ❤️（不点进去，像人刷着随手点）

**评论生成**（`xauto/comment.py`）：

1. 有模型 → 读完帖子写一句（当前接 DeepSeek `deepseek-flash`，即 v4.1 flash）
2. 没模型/调用失败 → 按帖子类型（吐槽/提问/教程/观点）套话术，引用只取短句
3. 模型输出会过一遍校验：超过 80 字、含「受益匪浅/说得很好」这类空话直接判不合格

**规则文件**：`xauto/comment_rules.md` 存在就会自动拼进 system prompt（优先级高于内置规则），
等你把那套评论规则给我，写进这个文件即可生效，不用改代码。

**LLM 密钥**：只从环境变量 `LLM_API_KEY` 读；拿不到时再读 `xauto/.llm_key`（已 gitignore）。
Windows 上 `SetEnvironmentVariable(...,'User')` 对已启动的进程不生效，所以留了这个文件兜底。

## 四、安全阀

| 阀门 | 位置 | 作用 |
|---|---|---|
| 去重簿 | `xauto/store.py` → `xauto/data/state.json` | 同一 tweet/会话只回一次，跨进程持久 |
| 限额 | `config.DEFAULT_BATCH` / `-n` | 单轮最多做几条 |
| 冷却 | `config.ACTION_DELAY`（8~20s 随机） | 两条动作之间必等 |

另外：**默认 dry-run**，所有发出去的动作用命令都必须显式加 `--yes`。

## 五、两个「看起来像被锁了」的坑

### 坑 A：残留的透明 mask 吃掉全部指针事件（2026-11-16）

现象：发帖按钮 rect 正常、坐标也对、点击不报错，但**页面毫无反应**，
真实鼠标点也一样（用户原话：「点击发帖好像被锁定了」）。

根因：X 的浮层（`Unlock more on X` 这类）关闭后偶尔留下 `div[data-testid="mask"]`，
它是一层全屏透明遮罩 —— `document.elementFromPoint(按钮中心)` 返回的是 mask 而不是按钮，
所有 pointer 事件都被它吞掉。

处置（`XPage.dismiss_mask`，按侵入性从低到高）：

1. 点浮层自己的关闭按钮（`data-testid="app-bar-close"`）
2. 点遮罩本身（X 里点遮罩 = 关闭当前层）
3. 发送 ESC
4. 都不行 → 返回 `stuck`，**不要硬点**（硬点只会喂风控）

配套：`click()` 做「点前命中测试」（`_hit_test`）：目标 rect 中心处 `elementFromPoint`
必须是它自己或它的子孙，否则先清浮层再点。

### 坑 B：`return` + 换行的自动分号插入（ASI）

```python
# 错：`return` 后面换行，JS 立刻插入分号 → 函数恒返回 undefined
self.eval(f"return {js};")     # ← 永远 False，命中测试形同虚设

# 对：整段作为函数体传进去，return 与表达式同行
self.eval("const t = ...;" "return !!hit && (hit === t || t.contains(hit));")
```

这个 bug 伪装性极强：不报错，只是「永远判定被遮挡」，于是每次点击都先去清浮层，
表现为「点半天发不出帖」，很容易误判成账号被限。

## 六、抗风控：输入形态比「用什么工具」更重要

> 2026-11-16 记：第一版用 `Input.insertText` 把整段文本一次灌进编辑器，
> 配合随后的 `location.assign` 导航 + 轮询刷新，账号很快进入受限状态
> （`/i/graduated-access` + 「Unlock more on X」浮层）。
> 结论：**问题不在 CDP 本身，而在「事件形态」和「操作节奏」**。

改动（`xauto/typing.py`）：

| 维度 | 错误做法 | 现在的做法 |
|---|---|---|
| 中文输入 | 一次 `insertText` 灌整段 | IME 组合提交：`imeSetComposition` + `insertText`，每次 3~6 字，间隔 120~450ms |
| 英文输入 | 同上 | 逐字 `dispatchKeyEvent`（keyDown 带 text → 浏览器自生成 keypress） |
| 鼠标 | 瞬移到坐标点击 | 缓动轨迹（9 段 `mouseMoved` + ±1.5px 抖动）→ 悬停 → 按下 → 松开 |
| 提交时机 | 填完立刻回车 | 提交前停 1.8~4.2s（真人会扫一眼） |
| 页面切换 | `location.assign` 批量跳转、反复 reload | 优先复用当前页；必须跳转才用，且跳完等渲染 |
| 读数据 | 立刻读一次空列表就判定失败 | `wait_tweets()` 轮询等渲染（新号限速时页面会转圈好几秒） |

额外注意：

- **新号限制是平台行为，不是脚本 bug**。新注册账号会收到「Unlock more on X」：
  内容不被检索/推荐、私信会被过滤。只能靠正常使用一段时间累积信任。
- 资料页会有「Let's get you set up」清单（关注 5 个账号 / 关注 3 个话题 / 完善资料 / 开通知）。
  把它走完，浮层基本就不再弹，账号信任也会好一些。
- 遇到浮层挡住编辑器，走 `dismiss_blockers()`（只点 Got it / 知道了 这类按钮），
  不要靠刷新页面清场 —— 刷新本身也是异常信号。
- 写操作（发帖/回复/私信）必须限量：新号建议每天个位数，间隔 >10 分钟。

### 事故记录：2026-11-16 发帖链路验证引发风控刷新

**过程**：先自检两次（不发布）→ 发一条正常内容做端到端验证。
接口侧一切正常：`Your post was sent. View` toast 拿到、编辑器清空、只点了一次提交。
但随后 1 分钟内查看主页，**这条新帖没有出现在自己的时间线上**（前两条是更早的帖子）。

**判断**：
- 不是脚本没发出去 —— toast 是 X 的成功回执；
- 更可能是新号受限状态：内容进得去、但不进主页时间线/检索（与 `Unlock more on X`
  里写的「Be seen by more people」对得上）；
- 而在受限期反复查看主页/等待渲染，被判定为「异常刷新」，触发了风控刷新。

**结论与纪律**：
1. 受限期内，**任何写操作前先确认账号状态**，不是「能点通」就可以发；
2. 验证「发帖成功」不要靠回主页看 —— 主页时间线对受限号有延迟/屏蔽，看 toast + 编辑器清空即可；
3. 一旦怀疑触发风控：**立刻停所有写操作**，页面别动，等平台自己恢复（小时级到隔天级）；
4. 恢复后先用只读接口观察 1~2 次会话，再考虑低频发布。

## 七、排错速查

| 现象 | 先看什么 |
|---|---|
| 端口连不上 | `python tools/x_launch.py --status`；窗口是否被关掉 |
| 点哪儿都没反应 | 是不是残留 mask：`dismiss_mask()` 的返回值是不是 `mask-click` / `close-button` |
| 点不动 | 窗口是否最小化（最小化时浏览器丢弃 CDP 输入）；用 `--shot` 看当前画面 |
| 选择器失效 | `python tools/x_probe.py --tree '<选择器>'` 看 DOM 是否改版 |
| 编辑器校验不过 | 看 `xauto/data/shots/1-*-filled.png`：是被 X 截断还是根本没注入 |
| 点了没反应 | `xauto/data/shots/2-after-*.png` + toast 文本；X 有时要求二次确认 |
| 时间线一直转圈 | 新号限速，等；`wait_tweets()` 会轮询，别连续刷新 |
